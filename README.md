`ovst_service_time` **ใช้ไม่ได้** — หยุดบันทึกตั้งแต่ 16 มี.ค. 2569

| `service12` | ตรวจเสร็จ (ทันตกรรมบันทึกแค่ตัวนี้) | ห้องตรวจ, ทันตกรรม |

ความหมายของคอลัมน์ข้างบนเป็นของ รพ.วังน้ำเขียว — รพ.อื่นอาจกดเวลาลงคอลัมน์ต่างกัน (เช่น รพ.สงขลา คัดกรองไม่ได้กด
`service4`/`service11` เวลารอพบแพทย์จึงขึ้น “–”) ตรวจได้ที่หน้า `/check` และกำหนดใหม่ด้วย env `OPD_ST_MAP`
(`stmap.py` เปลี่ยนชื่อคอลัมน์ผ่าน derived table ทุกคำสั่ง SQL จึงยังอ้าง `service4`, `service11` … ตามเดิม)
ที่วังน้ำเขียว `opd_dep_queue` แทบไม่มีข้อมูล (ไม่มีเวลารับคิวเลย) จึงยังคิดเวลารอจาก `service_time`

### ส่วนวิเคราะห์คอขวด (Bottleneck Analysis, เพิ่ม 17 ต.ค. 2569)

ใช้ติดตามผลการปรับปรุง 3 จุดที่พบจากข้อมูลวันทำการ 16 ก.ย. – 16 ต.ค. 2569:
ผู้ป่วยราวครึ่งหนึ่งมาถึง 06:00–08:59 แต่แพทย์เริ่มตรวจ ~08:05–08:25 และพีค 09–11 น. (นัด 08:00 ถึง ~87%),
ผู้ป่วยที่เจาะ Lab ก่อนพบแพทย์ค้างที่คัดกรอง ~70 นาที, รอรับยาช่วง 09–11 น. ~50–60 นาที เทียบบ่าย ~25–33 นาที
ทุกบล็อกแสดงเฉพาะชั่วโมง 06–16 (`BN_FROM`, `BN_TO`) และตัดช่วงเวลาที่ติดลบ/เกิน 6 ชม. เหมือนตาราง SLA

| # | บล็อก | ที่มา |
|---|---|---|
| 11 | ผู้ป่วยมาถึง vs แพทย์เริ่มตรวจ รายชั่วโมง | มาถึง = `hour(ovst.vsttime)` · เริ่มตรวจ = `hour(service5)` (≥ 06:00) · เส้นส้ม = รอพบแพทย์ `service11`→`service5` ตามชั่วโมงที่ลงทะเบียน · แพทย์เริ่มตรวจคนแรก = เฉลี่ย `min(service5) ≥ 06:00` ต่อวัน เฉพาะ จ.–ศ. ไม่นับ ER (`OPD_ER_DEP`, ดีฟอลต์ `011`) |
| 12 | การกระจายเวลานัดหมาย | `oapp.nexttime` ของนัดที่ `nextdate` ตกในช่วงที่เลือก · Top 5 เวลา + อื่น ๆ + ไม่ระบุเวลา (`NULL`/`00:00`) |
| 13 | Lab TAT ผู้ป่วยนอก | `lab_head` สั่ง → รับสิ่งส่งตรวจ → รายงานผล ตาม `hour(order_time)` · เฉพาะ `ovst.an is null` และสั่ง/รับ/รายงานในวันเดียวกับ visit · ตัดทั้งใบถ้าช่วงใดผิดปกติ (สองช่วงจึงรวมเท่ากับ TAT) · เป้า ≤ 60 นาที (`OPD_TARGET_LAB_TAT`) |
| 14 | เวลาคัดกรอง มี Lab vs ไม่มี Lab | `service4`→`service11` ของ visit ไม่ admit · มี Lab = มี `lab_head` วันเดียวกันที่ `order_time` ก่อน `service5` (ถ้าไม่มี ใช้ `service11`) |
| 15 | เวลารอรับยา รายชั่วโมง | `service6`→`service16` ตาม `hour(service6)` · เป้า = แถว "รอรับยา" ใน SLA (20 นาที) · แท่งจาง = < 30 ใบสั่ง |
| 16 | ตารางรายแผนก (เว็บเท่านั้น) | ทุกแผนก ค้นหา/เรียงคอลัมน์ · “ดู ›” = หน้ารายเคส `/cases` |
| 17 | แนวทางลดระยะเวลารอคอย | `queries.recommendations` — กฎจากตัวชี้วัดของช่วงที่เลือก แต่ละข้อขึ้นเมื่อเกินเกณฑ์ พร้อมตัวเลขอ้างอิง เรียงตามสัดส่วนที่เกินเป้า (นัดกระจุก, แพทย์เริ่มช้า, รอผลแล็บ, Lab TAT, รอรับยา, รอพบแพทย์, ผิดนัด ≥ 20 นัด, เวลาบันทึกไม่ครบ) |

สีแท่ง/ตัวเลขใช้เกณฑ์เดียวกับบล็อก 10: เขียว = ถึงเป้า, ส้ม = เกินเล็กน้อย, แดง = เกิน ≥ 1.5 เท่า

**ความพึงพอใจผู้ป่วย** ในภาพต้นแบบ HOSxP ไม่มีข้อมูล จึงแทนด้วยตัวชี้วัดจริง:
KPI ช่อง 6 = % จบบริการภายใน 2 ชม., บล็อก 8 = สิทธิการรักษา + กลุ่มโรคหลัก — ไม่มีตัวเลขสมมติ

เป้าหมาย (SLA, เวลารวม ≤ 60, ผิดนัด ≤ 10%, ฯลฯ) ตั้งตามภาพต้นแบบ แก้ได้ที่หัวไฟล์ `queries.py`
(`OPD_TARGET_TOTAL`, `OPD_TARGET_PEAK` ตั้งผ่าน env ได้)

## ผังผู้ป่วย OPD แบบ 2.5D (`/flow`, เพิ่ม 17 ต.ค. 2569)

ภาพจำลองผัง OPD แบบมุมมอง isometric หุ่นผู้ป่วยนั่งรอตามจุดบริการและเดินไปจุดถัดไปตามเวลาที่บันทึกใน HOSxP
(แนวเดียวกับวิดีโอตัวอย่าง `vdo.mp4`) — เปิดจากปุ่ม "🏥 ผังผู้ป่วยสด" บนแดชบอร์ด

- **โหมดสด**: วันนี้ เวลาเดินตามนาฬิกาจริง ดึงข้อมูลใหม่ทุก 1 นาที (แคชฝั่งเซิร์ฟเวอร์ 45 วินาที `OPD_FLOW_TTL`)
- **เล่นย้อนหลัง**: เลือกวันที่ / ลากกราฟไทม์ไลน์ / ความเร็ว ×1–×300 · `?d=2026-10-16&t=09:30` เปิดที่วัน-เวลานั้น
- `?tv=1` ซ่อนตัวควบคุม สำหรับจอทีวี · ปุ่ม ⛶ เต็มจอ · คลิกชื่อจุดในแผงขวาเพื่อซูมไปที่จุดนั้น
- **ชี้เมาส์ / แตะที่หุ่น** ดูเวลารอที่จุดนั้น เทียบเป้าหมาย เวลาอยู่ใน รพ. ระดับความเร่งด่วน และเพศ (ไม่มีข้อมูลระบุตัวตน)
- ป้ายชื่อจุดลอยเหนือผนังด้านหลัง ถ้าชนกันจะเลื่อนป้ายด้านหลังขึ้นแล้วลากเส้นชี้ลงจุด
- หุ่นผู้ป่วย: **เสื้อ = ความเร่งด่วน** (ER ใช้ `er_regist.er_emergency_level_id` ระดับ 1–4,
  OPD ใช้ `ovst.pt_priority`: 4 ฉุกเฉิน → ส้ม, 2/3 พระภิกษุ-ผู้พิการ/ผู้สูงอายุ → ม่วง, อื่น ๆ → ขาว) ·
  สีคัดแยกตาม สธ. แต่ระดับ 2 ใช้ส้มแทนชมพู ไม่ให้ซ้ำกางเกงผู้หญิง ·
  **กางเกง + ทรงผม = เพศ** (`patient.sex`: ชายกางเกงฟ้าผมสั้น, หญิงกางเกงชมพูผมยาว) ·
  **อีโมจิเหนือหัว** 😤 = รอที่จุดนั้นเกินเป้า, 😡 = เกิน ≥ 1.5 เท่า (เป้าหมายใน `flow.AREAS`)
- ป้ายชื่อจุด/แถบสีขอบพื้น = เวลารอเฉลี่ยของจุดนั้น (เขียว/ส้ม/แดง เกณฑ์เดียวกับบล็อก 10)

ตำแหน่งผู้ป่วย **อนุมาน** จากขั้นล่าสุดที่กดเวลาแล้ว (`flow._segments`):

| เวลาที่บันทึก | ไปอยู่ที่ |
|---|---|
| `vsttime` | ห้องบัตร |
| `service3` / `service4` | จุดซักประวัติตาม `service4_dep` (OPD, NCD, ARI, ER …) |
| `lab_head.order_time` / `receive_time` | รอเจาะเลือด / รอผลแล็บ |
| `service11` | หน้าห้องตรวจ (หรือหน่วยเฉพาะ เช่น ARI, ER, ทันตกรรม) |
| `service5` | ห้องตรวจตาม `service5_dep` (021–024 = ห้อง 1–4, 033 = ห้อง 5, 040 = Telemed) |
| `service12` | ไปห้องยาถ้ามีขั้นยาตามมา ไม่งั้นการเงิน ไม่งั้นกลับบ้าน |
| `service6` / `service7` | ห้องยา / การเงิน (`service7_dep` ของ ER, ทันตกรรม = จ่ายที่หน่วย) |
| `service16`, `service20` | เสร็จ → ไปขั้นถัดไปหรือกลับบ้าน |

- ไม่นับเวลาที่เวชระเบียน (`001`) บันทึก — เป็นงานส่งต่อ/ปิด visit ย้อนหลัง ไม่ใช่ที่อยู่ของผู้ป่วย
- **ออกจาก รพ.**: ขั้นสุดท้ายเป็น "เสร็จ" (ตรวจเสร็จ/จ่ายยาเสร็จ) → ออกใน 2 นาที · ขั้นสุดท้ายยังค้าง → อยู่ต่อได้ตาม `LINGER`
  · **ส่งกลับบ้าน `ovst.cur_dep = 999`** ใช้ `cur_dep_time` เป็นเวลาออกเมื่อกดหลังกิจกรรมสุดท้ายไม่เกิน 120 นาที
  (ที่ รพ.วังน้ำเขียว 281/365 visit กด 999 ก่อนรับยา จึงใช้เวลา 999 ตรง ๆ ไม่ได้ — ถ้ากดก่อน ให้ค้างได้ไม่เกิน 30 นาที)
- **ห้องบัตรหน้า ER** (`REGER`): ผู้ป่วยที่แผนกหลักเป็น ER ลงทะเบียนจุดนี้ · ห้องตรวจแสดง **ตรวจแล้ว N ราย** (นับการเข้าห้องจนถึงเวลาจำลอง)
- **❤️ ได้รับบริการทันเวลา**: ออกจากจุดรอ (ซักประวัติ, หน้าห้องตรวจ, แล็บ, ห้องยา, การเงิน, คลินิกเฉพาะ) ภายในเป้าหมายของจุดนั้น
  — ไม่นับห้องบัตร (ทุกคนผ่านใน 2 นาที) ห้องตรวจ และ ER
- **ห้องฉุกเฉิน**: เข้า ER ที่ `er_regist.enter_er_time` อยู่ 20 นาที (สังเกตอาการ `observe='Y'` 180 นาที) แล้วไปขั้นถัดไป/กลับบ้าน
  (`finish_time` = เข้า + 10 นาทีเสมอ, `leave_datetime` ว่าง จึงใช้ไม่ได้) · ER ไม่คิดเวลารอและความหนาแน่น
- **ไม่แสดงในผัง**: ผู้ป่วยใน (`ovst.an` ไม่ว่าง) · Telemed · PCU (`pt_subtype ≠ 0`) — นับแยกในแผงขวา
- **รอ** ในแผงขวา = ค่ากลาง (มัธยฐาน) ของคนที่อยู่ในจุดนั้น · **ความหนาแน่น** = คน ÷ ที่นั่ง (`cap` ใน LAYOUT หรือนับเก้าอี้ในผัง)
  < 45% ว่าง · 45–79% ปานกลาง · ≥ 80% แน่น · ภาพรวมไม่รวม ER
- ขั้นสุดท้ายไม่ใช่ "จบ" (ลืมกดเวลา) → อยู่ที่จุดนั้นได้นานสุดตาม `LINGER` แล้วหายไป
- **Telemed (`main_dep` 040) ไม่วาดในผัง** — ลงทะเบียนล่วงหน้าพร้อมกัน 06:00 น. ไม่มีใบสั่งยาถึงห้องยา/ไม่ชำระเงิน
  จึงถือว่าผู้ป่วยไม่ได้อยู่ใน รพ. นับแยกในแผงขวา (แก้ได้ที่ `OPD_FLOW_REMOTE_DEPS`, คั่นด้วย `,`) **— รอยืนยันกับหน้างาน**
- ผังไล่จาก**แผนผังอาคารและบริเวณ** [`docs/floorplan.jpg`](docs/floorplan.jpg) (ได้รับ 17 ต.ค. 2569) —
  `LAYOUT` / `DECOR` / `BUILDINGS` / `WALKS` / `DOORS` หัวไฟล์ `static/flow.js` ใส่พิกัดเป็น**พิกเซลบนภาพผัง**
  (`px(ซ้าย, บน, ขวา, ล่าง)`, 8 px ≈ 1 ม.) แก้ได้โดยวัดจากภาพตรง ๆ
- ปรับตามหน้างาน (17 ต.ค. 2569): X-ray เล็กลงและย้ายไปติดคลินิก NCD · ที่นั่งรอรับยาขยายเต็มแนวหน้าห้องยา · โถงหน้าห้องตรวจขยายเป็น 2 แถว (แถวในรอผลแล็บ,
  แถวติดห้องตรวจรอพบแพทย์) · สุขภาพจิต (`049`) ต่อจากห้องตรวจ 5 หน้าห้องยา ·
  กายภาพบำบัด (`042`) เป็นอาคารแยกห่างออกไปหลังห้องยา (มีทางเดินเชื่อม) และแพทย์แผนไทย (`041`) อาคารอีกฝั่งของกายภาพ · ปฐมภูมิ (`020`) อยู่อาคารอำนวยการ ·
  ห้องยาอยู่ฝั่งอาคารกายภาพ ช่องจ่ายยาหันเข้าโถง OPD — ผู้ป่วย "รอรับยา" นั่งในโถงหน้าช่องจ่ายยา ถัดลงมาเป็นการเงิน
- ห้อง Telemed (`040`) ย้ายไปอาคารปฐมภูมิ (ระหว่างทันตกรรมกับปฐมภูมิ) ห้องเดิมใช้เป็นห้องตรวจ 1 (`021`) ·
  ห้องตรวจ 4 (`024`, ~1,000 visit/เดือน) แยกเป็นจุดของตัวเองแล้ว (ก่อนหน้านี้ถูกนับเป็นห้อง 2)
- ยังเป็นสมมติฐาน **— รอยืนยันกับหน้างาน**: จุดซักประวัติ = โถงฝั่งทางเข้าข้างห้องบัตร · การเงิน = โถงหน้าห้องยา
- ผู้ป่วยเดินมาจากลานจอดรถทางใต้ตามถนนฝั่งตะวันออก แล้วเข้าประตูของแต่ละอาคาร (OPD, ARI, ER, อาคารอำนวยการ)
- ความเป็นส่วนตัว: API ส่งเฉพาะนาทีที่เข้า-ออกแต่ละจุด + รหัสสุ่ม 10 หลัก (sha256 ของ vn ผสมเกลือ
  `OPD_FLOW_SALT`) + เพศ + ระดับความเร่งด่วน ไม่มี vn / HN / ชื่อ / อายุ

## หมายเหตุทางเทคนิค

- สตริงไทยใน SQL จะเพี้ยนเพราะ connection เป็น tis-620 — ค่าแทน NULL ("ไม่ระบุแผนก") ใส่ฝั่ง Python
- `db.py` โหมด ssh ใส่ `stdin=DEVNULL` + `BatchMode` ไม่งั้น ssh ของ Windows ค้างเมื่อรันใต้ dev server ที่ไม่มี console
- `render.py` สตาร์ตแอปด้วย `FLASK_DEBUG=0` เพื่อไม่ให้ reloader ทิ้งโปรเซสลูกค้างไว้
- `render.py` เปิดหน้าต่างสูง 4800 px แล้วตัดพื้นหลังส่วนเกิน (หน้ายาวขึ้นหลังเพิ่มบล็อก 11–15 และ 17)
- แคชผลลัพธ์ 120 วินาที (`OPD_CACHE_TTL`, 0 = ปิด) เก็บสูงสุด 32 ช่วงวันที่ต่อ worker (`cache.py`) · พอร์ต **5900**
- ค่าที่ผู้ใช้กรอก (วันที่ รหัสแผนก) ส่งเข้า SQL เป็นพารามิเตอร์เสมอ `fetch(sql, {"d1": d1})` — `%` ที่เป็นตัวอักษรใน SQL ต้องเขียน `%%`
- ดึงข้อมูลได้ไม่เกิน 366 วันต่อครั้ง (`OPD_MAX_DAYS`) · คำสั่ง SQL ถูกตัดเมื่อเกิน 60 วินาที (`OPD_DB_TIMEOUT`)
- `FLASK_DEBUG=1` เปิด debugger และฟังแค่ 127.0.0.1 — อย่าเปิดบนเครื่องที่ผู้ใช้เข้าถึงได้
- ทดสอบ: `pip install -r requirements-dev.txt && python -m pytest` (ไม่ต้องต่อฐานข้อมูล)
